# Initial cursor key registration qualification

This trusted native fixture extends the existing Control migration laboratory.
It uses a fresh PostgreSQL16.15 database and the actual exact-revision executable.
Run only after the enclosing owner has inventoried free space, processes, all
containers/mounts/networks/volumes and preserved active or retained dependencies.
No global cleanup, old data reuse or release qualification is involved.

The selected checks are initial migration/registration, exact public key bindings,
same-registration retry with unchanged SQL, missing/partial/conflicting keys,
missing schema/privileges, partial registration/audit omissions and forbidden
history mutations, engine restart and COMMIT-loss/concurrent resolution. Expected
key hashes come from the committed Python/hashlib fixture, not the Rust adapter.
Actual native results and exclusions must be recorded separately; this authored
recipe alone is NOT_RUN.

Use the existing `experiments/control-migrations/lab.py setup` after an exact
native build, with a new owned root and unique run name. `run.py --root ROOT`
owns only its newly created databases and records each original result under that
root. The surrounding orchestrator must preserve logs, safe evidence, private
keys, source/build manifests and data, then stop only its labeled resources.
The fixture does not qualify key activation, rotation, cross-worker distribution,
page semantics, host power loss or the ordinary Compose release journey.
