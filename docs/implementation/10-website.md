# Phase 10 — Website, documentation, blog and adoption specification

Status: **planning only; proposed product commands and tests are not executed**. All proposed files, examples, commands, builds and publication rehearsals below are future implementation work; none ran while this specification was written. This is the new website phase, not the legacy Go phase-10 consolidation. The current repositories and website remain read-only references until their respective migration/publication is explicitly authorized.

**Goal:** deliver a complete static project website that explains what BigBrotr does, teaches installation and recovery from shipped artifacts, supports integrations and publishes useful versioned research/release content.

**Architecture:** `apps/site/` uses Astro/Starlight with schema-validated content, static output and an independent release lifecycle. Canonical English prose lives once in its owning `docs/reference/`, `docs/operations/`, `docs/tutorials/` or new `docs/user/` source; build-time loaders render it, while generated CLI/config/API reference comes from owning schemas and commands. The site has no live archive, database, management credentials or Node runtime requirement. The dashboard/private panel are separate P09 artifacts and remain instance applications.

**Inputs:** [product/site contract](../product/dashboard-and-website.md), [historical inventory](../research/product-surfaces-findings.md), [requirements](../product/requirements-and-history.md), [repository contract](../engineering/rust-and-repository.md), [P08 operations](08-operations.md), [P09 interfaces](09-product-interfaces.md), P01–P07 versioned behavior and central data/interface dictionary. BigBrotr is the product name; `bigbrotr-rs` is the public development repository (Q42). Never present an unbuilt proposed command or unqualified artifact as a working installation path.

## Content and evidence contracts

Primary navigation: Product, Get started, Documentation, Developers, Blog and Releases. Secondary About/Community/Security/Roadmap links remain discoverable. “Explore an instance” appears only for an explicitly maintained, configured destination with operator identity; a public demo and its service commitment are not silently created by a site deployment.

Every guide carries `id`, `title`, `description`, owning responsibility, supported product versions, source path, related acceptance case IDs, verification date/status and lifecycle `current|unreleased|legacy`. Tutorials additionally identify exact artifact/version and expected observable outcomes. Research posts carry author, publication/revision dates, corpus/query provenance, method/version, limitations and revision log. Release records bind exact artifact digests, platform/API/storage compatibility, documentation line and migration/rollback constraints. No “last updated” timestamp is fabricated from a rebuild.

Before first release, `/docs/next/` is explicitly unreleased; it is not silently relabeled stable. At a release, `apps/site/src/data/versions.json` maps supported lines to immutable documentation snapshots and corrections metadata. `/docs/latest/` resolves to the selected stable line. Version switches preserve topic ID when available, otherwise show that topic's absence and alternatives; they do not land on an unrelated page. Search defaults to the chosen supported line, with blog/legacy results labeled and optionally included.

P01-T08 owns `tests/acceptance/run.py` and its result schema. Add `tests/acceptance/cases/site.py`; register exactly `p10-t01` through `p10-t10`. The canonical proposed command is illustrated by `python3 tests/acceptance/run.py p10-t01 --binary dist/bigbrotr --compose packaging/compose/acceptance.yaml --evidence .research/implementation/p10-t01`; the other tasks use their named case IDs and evidence directory. Retain site/artifact/schema/source digests, route inventory, verification outcomes, browser/OS, independent oracle output, example transcript and screenshots with secrets removed. A skipped required clean-machine example is NOT RUN, not passing documentation.
