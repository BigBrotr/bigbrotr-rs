# Static configuration reference

Generated by `bigbrotr config reference` from the same Rust registry used by the parser and JSON Schema.

This initial schema resolves candidate roots, selected roles and resource arithmetic. It does not activate managed/declarative authority, open engines, establish ownership or enable runtime services. Remaining service-specific settings and adapters are explicit implementation work; unknown keys fail. `doctor` returns exit 4 while live authority/adapter checks are unavailable.

Use `bigbrotr config init --recipe full --output instance.toml`, then `config validate --file instance.toml` or `config show --file instance.toml`. Initialization creates candidate IDs and refuses any existing output path. A copied ID is not an ownership grant. Fixed examples contain reserved `.example` destinations and need operator enrollment before future acquisition.

`validate` is offline and never resolves secret references. `show` is a diagnostic document, not a round-trippable configuration: byte values and durations are normalized to bytes/microseconds and unsigned integers are decimal strings. Dependent defaults identify their source key and any microsecond offset; monitor stored checks follow the chosen computed set, and the default API timeout follows the read timeout plus 5s. Secret references and relay path/query values are redacted. Structured revisit bands use start_age/end_age/cadence with explicit durations, ordered nonoverlapping intervals and a positive cadence; their normalized diagnostic durations are decimal microseconds. Desired/applied revisions stay null until Control exists. No environment override stack is read.

Storage-root comparison removes repeated separators and trailing slashes; configured paths stay intact, and filesystem links and mounts remain runtime checks.

Static validation checks the declaration, not live engine versions, TLS certificates, permissions, filesystem aliases, accepted-work drain capacity or measured memory. Limits are checked with u64 arithmetic; complete signed events remain invariant. JSON Schema documents shapes while the CLI enforces semantic relationships.

Exit codes: 0 requested output/static success, 1 I/O, 2 usage, 3 invalid configuration, 4 incomplete doctor checks. Input is a regular UTF-8 TOML file bounded to 10MiB, with the upstream parser's recursion bound. Values are not echoed in parse errors.

Missing static contracts remain explicit P01-T04 work: structured private routes/auth bindings/bans, observer allocation, directory sources, Geo sources, collection selectors, import scope/source shape, retention/maintenance plans, archive backend/provider roots and detailed derivation/ranking/read exposure/signing/publication/gateway policies. Cadence/resource templates for Deriver, Ranker and export do not implement target/profile/seed selection or finite export commands. Only the keys below are accepted; unsupported feature enablement is refused. No P01-T04 completion is claimed.

The six [recipes](../../config/recipes/) are static candidates generated by `config example --recipe NAME`; no installation or runtime qualification is implied. The split example assigns only sync locally and declares authenticated Control/Ingest/Archive owners. Local plaintext database routes require an explicit loopback/private-bridge boundary; cross-host routes use verify-full.
